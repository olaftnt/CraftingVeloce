# Module: furnace  (smelting, blasting, smoking)  -  machine: electric_furnace
#
# The explicit block matters: the mod has two furnaces. velocity_furnace burns
# FUEL, electric_furnace has the Forge Energy accumulator. Only the second has a
# charge to test, so the module name alone would resolve to whichever the
# registry lists first and the FE cases would measure a machine with no
# accumulator at all.
#
# Cases, in the order the module actually behaves:
#   1. accumulator at ZERO        -> must refuse, naming power as the reason
#   2. accumulator partly filled   -> must still refuse (too little for a smelt)
#   3. accumulator full            -> must deliver the item
#
# A freshly placed machine has NO charge, so case 1 is also the "did we forget to
# charge it" check. Testing only case 3 would pass on a machine that smelts for
# free - cases 1 and 2 are what prove the charge is really read. Case 3 after them
# proves a refusal does not leave the machine stuck.
#
# Watch it:  ./gradlew :neoforge:runTestClient -PveloceTest=module-furnace -PveloceKeepOpen

# --- case 1: no Forge Energy at all ---
/cv testmodule furnace electric_furnace
expect: building and waiting

/cv testmodule fe 0
expect: FE set to

wait: 120

/cv testmodule result
expect: FAIL

# --- case 2: some energy, but not enough for one smelt ---
/cv testmodule furnace electric_furnace
expect: building and waiting

/cv testmodule fe 1
expect: FE set to

wait: 120

/cv testmodule result
expect: FAIL

# --- case 3: full accumulator ---
/cv testmodule furnace electric_furnace
expect: building and waiting

/cv testmodule fe 1000000
expect: FE set to

wait: 120

/cv testmodule result
expect: PASS
